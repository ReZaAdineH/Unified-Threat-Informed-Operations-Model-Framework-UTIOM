# UTIOM Ecosystem

The **UTIOM Ecosystem** is a growing family of connected Security Operations models, capability instruments, context services and practitioner resources built around one central idea:

> **Security Operations should operate as one threat-informed system rather than a collection of disconnected functions.**

UTIOM remains the overarching operating model. Current framework release: **v1.4**.

## Canonical UTIOM architecture

**Three pillars:** Leadership & Governance; Engineering & Enablement; Operations & Analysis. Leadership & Governance is the management and control plane.

**Seven phases:** Vision → Strategy → Crown Jewels → Threat Visibility → Threat Detection → Response → Continuous Improvement.

**Three cross-cutting enablers:** Talent, Validation, Threat Hunting. They are not phases.

**STRATA:** Strategy, Talent, Resilience, Automation, Telemetry, Adaptability.

**Three assessment tiers:** Strategic & Governance Foundation; Engineering & Operational Capability; Assurance & Evolution. The tiers are an assessment/system-integrity view, not a replacement for the architecture above.

## Ecosystem at a glance

- **UTIOM** — overarching operating model.
- **TID-CMM** — deeper detection/visibility capability.
- **TIR-CMM** — deeper response readiness.
- **RSMM** — SIEM/monitoring-platform maturity.
- **Threat Hunting / Daily Hunt** — deeper operational hunting practice.
- **KEVMAP** — exploited-vulnerability/exposure context.

Supporting models/services can be recommended from assessment gaps, but they do not automatically raise or blend into UTIOM scoring.

## Community model

- Websites — canonical public presentation and tools.
- GitHub — versioned public knowledge, evidence and accepted changes.
- GitHub Discussions — durable public conversation where enabled.
- Slack — faster practitioner collaboration.

> **Slack is for conversation. GitHub is where durable knowledge, evidence and accepted framework changes live.**

The ecosystem can grow without adding lifecycle phases. New components should support, measure, validate or enrich the operating model rather than redefine it without evidence.
