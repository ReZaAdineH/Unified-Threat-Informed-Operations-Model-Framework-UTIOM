# About UTIOM

**UTIOM — the Unified Threat-Informed Operations Model — is an open Security Operations operating framework created by Reza Adineh.** It was developed to connect business purpose, threat-informed strategy, engineering discipline, Incident Response and Continuous Improvement into one coherent system.

## Why UTIOM exists

Modern Security Operations often accumulate tools, alerts, services and processes faster than they accumulate clarity. Governance, detection engineering, SOC operations and incident response can become separate disciplines with different priorities and weak traceability between them.

UTIOM was created to close that gap.

Its central idea is that Security Operations should be treated as a **living product and operating system**:

- start with purpose and business consequence;
- understand relevant threats;
- identify Crown Jewels and realistic attack paths;
- engineer the required evidence and telemetry;
- engineer and validate detections;
- prepare operational response before impact;
- measure outcomes;
- continuously improve the whole system.

## What UTIOM is

UTIOM is:

- a Security Operations operating model;
- a threat-informed lifecycle;
- a bridge between governance, engineering and operations;
- a way to design a SOC from scratch;
- an improvement system for existing internal, outsourced or hybrid SOCs;
- a framework for making capability traceable and measurable.

## What UTIOM is not

UTIOM is not:

- a SIEM or security product;
- a vendor architecture;
- a replacement for NIST CSF, ISO/IEC 27001, MITRE ATT&CK, SOC-CMM, NIS2 or DORA;
- a philosophy that equates more logs, more alerts or more detections with more security;
- a rigid waterfall process.

## Framework family

UTIOM sits at the operating-model level. Supporting public work includes:

- **TID-CMM** — Threat-Informed Detection Capability Maturity Model: https://tid-cmm.com
- **TIR-CMM** — Threat-Informed Response Capability Maturity Model: https://tir-cmm.com
- **RSMM** — Realistic SIEM Maturity Model: https://rsmm.rezaadineh.com/
- **KEVMAP** — exploitation/exposure context: https://kevmap.io

The Capability Dashboard also uses a derived STRATA lens to help interpret organisational constraints. These supporting concepts do not replace or extend the canonical seven UTIOM phases.

## Open framework and community

UTIOM is published as an open, living framework. The public repository exists so practitioners can read, cite, challenge, map and improve the public framework while keeping canonical doctrine maintainer-governed.
